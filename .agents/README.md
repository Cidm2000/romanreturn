# .agents/

GENERATED by `agentos sync`. Do not edit by hand — edit Agent OS and re-sync.

This is the portable half of the operating layer: the same lanes and rules Claude
Code gets through the plugin, as plain files, so Codex, Cursor, Aider, Gemini CLI,
a local model or a human can follow the identical model.

```
OWNER -> STRATEGIST -> COORDINATOR -> JUDGMENT LANES -> BUILDERS -> QA / REVIEW
```

A tool with no subagents follows the same path by reading the lane files and answering
their questions in its own reasoning. The judgment is the requirement; a subagent is
one way to get it.

- `routing.md` — which judgment lanes a request must pass through.
- `sources.md` — where authoritative evidence lives, by domain and by tier.
- `models.md` — which execution tier does which job.
- `portfolio.md` — how to reach the portfolio graph and the owner profile (pointers only).
- `gates.md` — the strategist procedure: the four gates before implementation, the
  MISSION handoff, and the outcome test after.
- `lanes/` — one file per lane: what it owns, its rules, and its report contract.

The kernel itself lives in the managed block at the top of `AGENTS.md`.
